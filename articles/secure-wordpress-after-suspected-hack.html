How to Secure a WordPress Website After a Suspected Hack

If a WordPress site shows unfamiliar users, redirects, injected content, or unexpected file changes, treat it as a potential incident. Avoid making rushed changes that destroy useful evidence or leave the entry point open.

Contact the host and preserve records

Use the host's verified support channel. Preserve available logs and a copy of the current site where practical before cleanup, following the host's incident guidance.

Secure privileged accounts

From a trusted device, reset administrator, hosting, database, domain, and related email credentials. Enable MFA and revoke unfamiliar sessions and application passwords.

Inspect users, plugins, and themes

Review administrator accounts, installed plugins and themes, recent updates, scheduled tasks, and unexpected files. Remove or replace compromised components using trusted sources.

Update and rotate exposed secrets

Patch WordPress core, plugins, themes, and server software. Rotate database and API credentials if exposure is suspected, and update dependent configuration safely.

Restore only from a trusted backup

Choose a backup known to predate the compromise, verify it, and fix the likely entry point before restoring. A restore alone may reintroduce the vulnerability.

Monitor and document

Check search results, redirects, security alerts, logs, and user reports after remediation. Keep a timeline of actions and retest the site.
